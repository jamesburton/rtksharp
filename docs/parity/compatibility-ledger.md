# RtkSharp / RTK (Rust) Compatibility Ledger

Phase 0 living document. Tracks (1) which of the seven Global-Constraints
parity categories have golden fixtures and where those fixtures live, and
(2) known/accepted output differences between the Rust `rtk` binary and the
in-progress `RtkSharp` .NET port. Later phases append to both sections as
filtering behavior is actually implemented — this document does not attempt
to be exhaustive at Phase 0, since most of RtkSharp's filter modules don't
exist yet.

Populated with differences already confirmed during Phase 1/2 work. Expected
to stay short until RtkSharp implements actual filtering (Phase 4+) — not
padded with speculative entries.

| `rtk grep -rln` / files-with-matches line order | Emits the file list in ripgrep's parallel directory-walker order, which is **run-to-run nondeterministic** (verified in Task 6: the *same* `target/release/rtk.exe` returned `RewriteEngine.cs, ShellLexer.cs` on 3 of 5 runs and the reverse on the other 2). | Identical: shells out to the same `rg` binary with the same flags (files-with-matches modes go through `GrepCommand`'s native passthrough), so it inherits the same nondeterministic ordering. | Line **order** in a files-with-matches listing is not part of the contract — the deterministic invariant is the *set* of matching files, which is byte-identical on both sides. `SystemParityTests.cs` treats an output pair that is equal as a sorted line multiset but unequal in index order as an ordering-only deviation (counted as matched, labelled `MATCH (rg ordering, nondeterministic)`); a missing/extra/changed line changes the multiset and still fails.
